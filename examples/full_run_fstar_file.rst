========================
Full run f_st example
========================

This file serves as a reference for a full run using the stochastic ``f_st`` workflow, in a python file instead of a notebook. This can be used on remote systems, e.g. in an HPC environment.
This example makes the following assumptions:

 - the global parameters for this run are specified as a yaml file under ``./parameters_fstar.yaml``
 - the underlying N-body input data has been generated by the THESAN simulation and resides under ``<scratch>/Thesan/``
 - during the simulation, intermediate and output data is written to ``<scratch>/thesan_run_fstar/`` (beware of the 100GB+ files this may generate)

What is different from the standard full run?
---------------------------------------------

This workflow uses the dedicated ``f_st``-grid solver:

 - ``beorn.precomputation.RadiationProfileFstSolver``

instead of the legacy single-``f_st`` solver.

The precomputed radiation profiles are stored on a grid of:

 - halo mass
 - accretion parameter ``alpha``
 - stellar fraction ``f_st``
 - redshift ``z``

and are represented by:

 - ``RadiationProfilesFStarGrid``

During painting, the ``PaintingCoordinator`` automatically switches to the stochastic ``f_st`` path when it receives a ``RadiationProfilesFStarGrid`` object.

In that mode:

 1. halos are grouped by the usual mass and accretion bins
 2. one ``f_st`` value is sampled for each halo
 3. the sampled value is mapped to the nearest precomputed ``f_st`` grid point
 4. the corresponding ``(mass, alpha, f_st, z)`` profile is painted

Stochastic ``f_st`` controls
----------------------------

The parameter file ``parameters_fstar.yaml`` adds the following controls under ``source``:

Profile grid definition:

 - ``f_st``
 - ``f_st_grid_min``
 - ``f_st_grid_max``
 - ``f_st_grid_n``

Painting distribution:

 - ``f_st_paint_distribution``
 - ``f_st_paint_sigma``
 - ``f_st_paint_min``
 - ``f_st_paint_max``
 - ``f_st_paint_seed``

Reproducibility
---------------

The stochastic ``f_st`` painting is reproducible per snapshot:

 - same snapshot index + same seed → same ``f_st`` assignments
 - different snapshot index → different RNG stream

Cache behavior
--------------

The cache is separated from the legacy workflow.

Radiation profile cache:

 - legacy: ``radiation_profiles_legacy``
 - ``f_st`` grid: ``radiation_profiles_fstar_grid_fmin_<...>_fmax_<...>_n_<...>``

Painted output cache:

 - legacy: ``painted_output_legacy``
 - stochastic ``f_st`` painting: ``painted_output_fstar_dist_<distribution>_sigma_<sigma>_seed_<seed>``

This prevents collisions between the standard and stochastic-``f_st`` workflows and ensures that changing the painting distribution, width, or seed changes the painted-output cache identity.

MPI notes
---------

The ``f_st`` workflow has been tested for:

 - MPI profile-cache round-trip
 - MPI painted-output-cache round-trip

Typical MPI usage:

.. code-block:: bash

   mpirun -n 2 python full_run_fstar.py
